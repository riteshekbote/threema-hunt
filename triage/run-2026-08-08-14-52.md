**Assets:** `ds-apip.threema.ch`, `api.threema.ch`, `apip.threema.ch` — `GET /identity/{id}` (200/404 oracle) + `POST /identity/fetch_bulk` (returns pubkeys for valid IDs, silent omission of invalid), CORS `*`, DELETE/POST/GET/OPTIONS, no 429/RateLimit/Retry-After (30 sequential POSTs all HTTP 200).

| Q | Answer |
|---|--------|
| Q1 Scope | ✅ `apip.threema.ch` in scope; `ds-apip.*` / `api.*` are the live hostname(s) serving the same directory API |
| Q2 Reachability | ✅ Public, unauthenticated |
| Q3 Impact | ✅ Mass identity+pubkey enumeration → targeted phishing/social-engineering, privacy breach at scale |
| Q4 Proof (read-only) | ✅ Confirmed: `GET /identity/ECHOECHO`→200, `GET /identity/ZZZZZZZZ`→404; `POST /identity/fetch_bulk {"identities":["ECHOECHO","ZZZZZZZZ"]}`→`{"identities":[{"identity":"ECHOECHO","publicKey":"..."}]}`; 30× POST at 1 rps → all 200, no 429 |
| Q5 Novelty | ⚠️ Known pattern in privacy-sensitive directories; within this program it is a confirmed unpatched finding |
| Q6 Not always-rejected | ⚠️ Borderline — CORS* + no rate-limit is a combination; the endpoint itself is by-design public. However **bulk fetch + silent omission + CORS* + no rate limit** moves it beyond mere "best practice" into a real scalable privacy impact |

**CVSS 3.1:** `AV:N/AC:L/PR:N/UI:N/S:U/C:L/I:N/A:N` — **4.3 (Medium)**. (Confidentiality = Low — identity existence + public key only.)
